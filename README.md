## 실험 조건

- 모델: `gpt-6-luna`, reasoning effort `none`
- 데이터: CoQA 100개, LongMemEval oracle 100개
- 모든 조건에 동일한 gold context 제공, 실제 검색은 생략
- Rewrite는 이전 이력으로 질문의 지시 대상·생략된 조건을 복원
- 지연은 rewrite와 답변 생성 시간을 합산
- LLM judge 미사용, 모든 조건에서 오류 0건
- **CoQA는 멀티턴 rewrite가 정상 실행된 최신 결과로 교체**

## CoQA 분석

**싱글턴 rewrite가 가장 높은 점수를 기록했다.** 이전 Q/A + 원문 조건 대비 EM **+9%p**, F1 **+0.119**이며, 평균 지연은 약 **2.13배** 증가했다.

| 멀티턴 raw 대비 | EM 차이 | EM bootstrap 95% CI | F1 차이 | F1 bootstrap 95% CI |
|---|---:|---:|---:|---:|
| 싱글턴 raw | −5%p | [−14, +4]%p | −0.049 | [−0.115, +0.019] |
| 싱글턴 rewrite | **+9%p** | [−1, +19]%p | **+0.119** | **[+0.036, +0.204]** |
| 멀티턴 rewrite | +4%p | [−6, +14]%p | +0.072 | [−0.013, +0.158] |

싱글턴 rewrite의 **F1 개선은 CI가 0을 제외**해 이번 표본에서 개선을 지지한다. EM 개선과 멀티턴 rewrite의 개선은 CI가 0을 포함해 확정하기 어렵다.

Rewrite 후 이력을 제거한 조건은 유지한 조건보다 EM **+5%p**, F1 **+0.048** 높았다. 입력 토큰도 **857→682개로 약 20% 감소**했다. 다만 두 조건의 직접 paired CI가 없고, rewrite를 각각 생성했으므로 **이력 유지 효과와 rewrite 내용 차이가 함께 반영**되어 있다.

## LongMemEval 분석

**질문 rewrite 단독의 추가 이득은 관측되지 않았다.** 원문 + gold context 대비 EM은 **43→39%**, F1은 사실상 동일했다. 평균 지연은 **1.75→3.13초**로 증가했다.

전체 이력을 유지한 rewrite 조건은 F1 **0.583**으로 가장 높았다. 전체 이력 + 원문 대비 EM **+2%p**, F1 **+0.029**지만, paired CI가 없어 개선의 확실성은 판단하기 어렵다.

LongMemEval에서는 gold context 자체가 과거 대화다. 따라서 전체 이력을 추가하는 조건은 같은 내용을 중복 전달하며, **현재 대화 이력과 검색된 과거 기억을 분리한 실험과는 차이**가 있다.

## 종합 해석

| 데이터 | 이번 결과가 보여주는 방향 |
|---|---|
| CoQA | 이력으로 질문을 rewrite한 뒤 gold 지문과 답변하는 방식이 유망 |
| LongMemEval oracle | 원문 + gold context를 기준으로 두고 rewrite의 추가 이득을 검증할 필요 |
| 공통 | 모든 멀티턴 질문에 rewrite와 전체 이력 유지를 일괄 적용할 근거는 부족 |

CoQA는 **이전 Q/A와 답변 근거 지문이 분리**되어 있어 질문의 문맥 의존성을 rewrite로 해소하는 효과를 보기 좋다. LongMemEval은 **gold context에 과거 대화가 이미 포함**되어 있어, 답변 모델이 원문 질문과 함께 문맥을 해석할 수 있다. 이러한 구성 차이가 rewrite 효과 차이에 기여했을 가능성이 있다.

## 한계 및 다음 검증

- 각 데이터 100개·단일 실행 결과이며, 데이터 간 절대 점수는 직접 비교하기 어렵다.
- LongMemEval의 EM/F1에는 단위·대체 정답·표현 차이의 영향이 남아 있다.
- Gold context를 고정했으므로 검색 성능 개선은 측정하지 않았다.
- 다음에는 **같은 rewrite 결과를 싱글턴·멀티턴 답변 조건에 공유**하고 직접 paired CI를 계산해야, rewrite 후 이력 유지의 효과를 더 명확히 판단할 수 있다.

**범용성과 리스크를 우선하면 ‘원문 질문 + 관련 이력 + 검색 결과’로 답변하세요. Rewrite는 검색용으로 사용하고 원문을 유지하세요.**

이 구성이 원래 의도와 문맥을 보존하면서, rewrite가 잘못 바꾼 질문에 답하는 위험을 줄입니다.

- **검색:** 이력으로 rewrite한 query 사용
- **답변:** 원문 질문 + 관련 이력 + 검색 결과 사용

관련 이력 선택을 아직 검증하지 않았다면 최근 이력을 유지하는 것으로 시작하세요. **이번 실험이 이 구성의 최적 성능을 입증한 것은 아니지만**, 최고 점수보다 정보 보존과 오류 대응을 우선하는 기본값으로 선택하겠습니다.
